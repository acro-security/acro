# Architecture

There are two ways in, and they share the engine:

- **Intercept.** A client points its HTTP proxy at `127.0.0.1:8081`. Acro
  records every exchange and streams it to the page; for HTTPS it terminates
  TLS with its own certificate authority, so the recorded message is plaintext.
- **Replay.** The Repeater sends one hand-written request through the same
  `replay.Engine`, no proxy involved.

mygo supplies the window, the system webview, the file dialogs and IPC — the
role Tauri plays for a Rust backend. It does not draw the interface. Everything
visible is TypeScript and CSS, and everything about the request is Go.

## Boundaries

| Layer                 | Owns                                                         | Does not                          |
| --------------------- | ------------------------------------------------------------ | --------------------------------- |
| `src/*`               | layout, interaction, drafts, history and context state, i18n | open sockets, read the filesystem |
| `src/mygo.ts`         | the typed client, generated by `mygo generate`               | any behavior                      |
| `main.go`             | the window, the bound service, app startup                   | any UI                            |
| `internal/replay`     | `Input`, `Result`, `Executor`, the transport                 | know a window exists              |
| `internal/capture`    | the proxy, its certificate authority, recorded `Traffic`     | know a window exists              |
| `internal/captureapp` | the proxy's lifetime, the traffic event, recent history      | any UI                            |
| `cmd/preview`         | the browser development transport, mirroring both services   | ship in the app                   |

`replay.Service` is the only crossing. It takes an `Input` and returns a `Result`
or an error, so a browser test, the desktop app and a future agent harness reach
the engine the same way.

## Development transports

The desktop app calls Go through IPC. A browser cannot, so `just api` serves
`POST /api/replay` from the same engine, with a strict origin check and a JSON
content type so a random page cannot drive the local engine. `src/api.ts` picks
the transport from `isMyGo()`, and both paths return the same `Result`.

## Concurrency and lifetime

IPC methods run on their own goroutines, so a slow request never blocks the
window; the page passes an `AbortSignal`, which cancels the Go `context.Context`
when the user cancels or the page navigates away. Nothing in the frontend holds
a Go value: state is JSON both ways.

The renderer receives only data. Requests, history, context and the chosen
request live in React state and are persisted to `localStorage`; the engine is
stateless between calls, which is what lets the same page run outside a window.

## Interception

The proxy listens on loopback only, so it is not exposed to the network. Plain
HTTP is forwarded and recorded as received. HTTPS arrives as a `CONNECT` tunnel;
the proxy answers it and then terminates TLS itself with a leaf signed by Acro's
local certificate authority (`internal/capture/ca.go`), which is stored under the
app's user data directory so the root a client installed keeps working across
restarts. A client trusts that root — Acro offers the PEM for download — and every
request inside the tunnel is recorded as plaintext.

Bodies stream without a transfer-size cap. Only the retained capture is bounded
to 2 MiB per direction; `truncated` marks a retained prefix, while the size fields
count all bytes forwarded. Binary prefixes use Base64 with separate request and
response encoding metadata. Upstream TLS advertises only `http/1.1` in ALPN: an HTTP/1.1 client cannot
read an h2 frame stream, which is the failure this pins down. Upstream redirects
are not followed — each hop is its own recorded exchange, as it should be for
traffic analysis.

HTTP and SOCKS5 share a listener with independent protocol detection per socket.
SOCKS payloads are classified again as plaintext HTTP or TLS. Tunnel HTTP uses
Go's HTTP server for framing, HEAD/204 responses, keep-alive, and trailers.
Stop cancels the listener generation and closes every accepted socket, including
unfinished greetings and hijacked tunnels. Start/stop and capture-history resets
are serialized so stale sessions cannot take over the listener or race clears.

A failed exchange is recorded with its reason rather than dropped: a TLS handshake
the client refused, an unreachable upstream, or a malformed response. That is what
makes the list useful when a target misbehaves.

`internal/captureapp` broadcasts each exchange through a mygo event and keeps the
newest 500 for a page that loads late. The browser transport mirrors the same
calls under `/api/capture/*` and pushes traffic over server-sent events, so what
you develop against in a page is what the app runs. SSE also pushes state changes;
the history endpoint restores the bounded session after a reload.

## Replay behavior

- HTTP(S) origin and an independently editable Host header
- Verified TLS, an explicit redirect policy, request timeout and cancellation
- Recomputed Content-Length after edits, preserved body bytes in the engine
- UTF-8 text or Base64 for non-UTF-8 responses, displayed up to 2 MiB
- Latest 100 session results, explicit context collection, and JSON export

The editor performs semantic HTTP replay through `net/http`, not byte-exact wire
replay: Go normalizes header casing and framing and may negotiate HTTP/2 for
HTTPS. The raw response is reconstructed for inspection. Chunked editor bodies
are rejected, so provide decoded content. Native editor buffers normalize line
endings; this is not a binary request editor.

## Agent harness direction

The future harness invokes `Executor` directly. Add a versioned tool registry
starting with `http.replay`, workspace scope, run IDs, durable execution events,
artifact IDs, cancellation and explicit execution policy before connecting model
providers. Human and agent callers should produce the same request and response
artifacts; the current Context export is an inspectable snapshot, not an agent
runtime.

Next capability slices are durable traffic storage, an explicit local proxy, an
interception queue, HTTPS certificate lifecycle, request comparison, controlled
batch replay and harness tools. Proxy interception, scanning, extension APIs and
model execution are not implemented. Acro independently implements capabilities
inspired by ZAP, Burp Suite and Caido rather than wrapping them.

## Project and session workspace

Workspace schema v3 stores projects, project-owned requests, open request IDs,
active project/session IDs, and local session drafts. The loader migrates schema
v1/v2 in the existing browser storage key. Closing a request tab changes only the
open list, not the saved draft. Project replay history and evidence are kept
separately in memory; the proxy listener and captured network traffic are global.

A session draft is a title and task instructions, with a JSON export and links to
project evidence. No model connection or assistant conversation is simulated.
Evidence is the former Context feature: explicit snapshots of replay requests
and responses, ready for later inspection or future harness integration.

Fresh workspaces have no projects or requests. Captured requests can be sent to
Repeater without creating a project. Their incremental capture numbers label rows and replay tabs; internal identities
keep saved drafts distinct across application restarts. The conversion preserves the captured Host and body, normalizes the
request target to origin form and removes transport framing headers. Binary or
incomplete request bodies are rejected explicitly. Reopening an existing capture
draft retains its edits.

`pretty.worker.ts` isolates Prettier and Shiki from the main UI thread. Only
Shiki-generated, escaped markup enters the preview. Formatting, decompression
and syntax coloring affect the read-only preview, leaving the stored request
and raw response untouched.

Preview results are shared in a session-wide memory LRU cache (128 entries,
32 MiB of retained strings). Cache keys include the complete source and MIME,
encoding, compression and HTTP options. Concurrent identical requests share one
worker job, and remounted views synchronously reuse the decoded, formatted and
highlighted result. Worker failures are retried on subsequent requests. The cache
is not written to browser storage and is discarded on reload.

## Native browser and credential executor

The top-level window now uses native Content to position the React shell WebView
and an independent guest WebView over the browser content slot. A ResizeObserver
reports logical bounds; guest views hide while React overlays are open, on
navigation away from Browser, or while the shell reloads. Guest pages use
`PageOptions.Untrusted` and project-specific persistent MyGo sessions. Their
navigation is limited to HTTP(S), and they cannot invoke Acro bindings or receive
application broadcasts.

`internal/vault` wraps the official Password Manager CLI using an isolated
profile and a memory-only unlock session. CLI errors are sanitized. Secrets enter
child processes through environment/stdin rather than command arguments. The
bound Vault facade returns only account metadata. Browser.Fill obtains the
current native page URL, checks exact origin against stored URIs, rechecks after
the credential lookup, and verifies origin and form action again in the page
executor before writing visible input fields. It never submits the form.
Future model tools must redact credential-bearing DOM and capture bodies before
export; this patch introduces no model connection or raw credential tool.
